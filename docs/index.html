从本体定义，
走到可验证的代码。

本体定义“有哪些事物、它们如何关联、必须满足什么约束”；图谱记录具体项目的需求、设计与代码事实；生成器沿显式映射实现一个受限切片，再由验证证据回答是否落实。

文档基线：开发元模型 2.0.0 · 2026-09-09。介绍仓库实现与方法设计；这是静态文档站，不是在线建模或代码执行工作台。未新增业务动作、函数或行为 DSL。

一张贯穿全流程的知识图谱

业务需求→ 约束契约条款→ 设计落实技术表示→ 转换代码产物→ 验证证据与判断

这些连接不只是流程图箭头，而是可查询的具名关系。例如 mappingSource / mappingTarget 记录业务与技术映射，preserves 声明生成应保留的条款，supportedByEvidence 记录判断依据。

需求改变时，可以沿关系找到受影响的设计、产物和验收条件；代码改变时，可以检查旧证据是否仍适用于当前快照。关系存在本身并不能证明实现正确。

阅读时始终区分三个结论

  1. 模型符合约束：当前数据通过已加载的校验规则，不代表需求完整。
  2. 转换规则可以生成：输入落在某个已实现适配器的支持范围，不代表任意业务都可自动生成。
  3. 实现得到验证：在特定模型、代码快照和验收范围内取得真实证据，不代表整个系统或生产发布就绪。

站点首页的运行记录是历史摘要，不是实时验证；文档中的简化片段也不是可直接批准执行的完整模型。
